# ترقية المنتجات والصور — المرحلة الأولى

تنفيذ المرحلة الأولى فقط من الطلب الجديد. تبقى روابط النماذج المستقلة لكل منتج ومعرض العميل وتحديث صورة الخيار، وتوسعة سجل الطلبات، ومركز الإعلانات وأحداث التحويل للمراحل التالية بعد الموافقة. لا يوجد نشر أو ربط Shopify أو إرسال أحداث إعلانية.

## سبب المشكلة المثبت في الكود

كان `productSchema` ومحرر المنتجات يدعمان `imageUrl` واحدًا عبر HTTPS، دون رفع ملفات أو حفظ محلي أو ترتيب صور. وكان نموذج العميل يعرض الرابط مباشرة بواسطة `next/image` مع `unoptimized`. لذلك لا يصح نسبة المشكلة إلى قائمة `remotePatterns` في Next.js؛ المسار القائم يطلب المورد من المتصفح مباشرة. قد يفشل المصدر بسبب انتهاء الرابط أو منع العرض الخارجي أو استجابة غير صورية، لكن لم يُقدّم رابط معطّل محدد أو سجل يثبت أيًا من هذه الأسباب لمتجر المستخدم.

## ما أصبح متاحًا

- رفع PNG وJPG/JPEG وWebP من الجهاز، حتى 12 صورة للمنتج، مع معاينة فورية أثناء الرفع ثم صورة النسخة المحفوظة.
- نقل الصور إلى الأمام والخلف وتعيين الرئيسية، وإزالة المرجع أو استبدال الصورة. فشل الاستبدال لا يمسح الصورة السابقة.
- استيراد صورة من رابط HTTPS لنطاق معتمد، والتحقق منها ثم حفظ نسخة محلية مستقلة. الرابط الذي يعيد صفحة HTML أو ملفًا غير مدعوم يُرفض.
- SKU للمنتج والخيار، ووصف حتى 2,000 حرف، وسعر مقارنة اختياري. الأسعار الأساسية وسعر كل خيار والمخزون الاختياري تبقى بالآلية القائمة.
- اختيار صورة للخيار من صور المنتج. **تحديث صورة الخيار في نموذج العميل ومعرضه الكامل يخصان المرحلة الثانية**؛ المرحلة الحالية تصلح حفظ الصور وعرض الصورة الرئيسية في النموذج القائم.
- نسخ المنتج بمعرّف منتج ومعرّفات خيارات جديدة وإفراغ SKU لتعديله قبل الحفظ. لا تُنسخ ملفات الصور مرة أخرى؛ المراجع داخل التاجر نفسه مشتركة بأمان.
- حذف آمن بتأكيد صريح: يختفي المنتج من القائمة العامة والخاصة الظاهرة، وتبقى بياناته وخياراته وصوره في التخزين لاستمرار سجل الطلبات والمخزون. لا تعني هذه العملية مسحًا نهائيًا للملفات. لا تُعدّل مسودة غير محفوظة بيانات المنتج عند حذفه.
- صورة مصغرة في جدول المنتجات، وحالة فشل واضحة للصورة القديمة بدل صورة مكسورة صامتة. لم تُعدّل أسعار الشحن أو ملفات الولايات والبلديات.
- إصلاح إغلاق نافذة المنتج خطأ عند إلغاء منتقي الملفات: حدث إلغاء الملف لا يُعامل بوصفه إغلاقًا للنافذة.

## التخزين والتحقق

تُفحص بايتات الملف وتُفك الصورة كاملة باستخدام `sharp`، ثم تُعاد كتابتها WebP دون EXIF أو ذيول الملف الأصلي. لا يُستخدم اسم الملف الأصلي في أي مسار. أسماء الملفات عشوائية بطول 256 بت، ويُرفض SVG والملفات التنفيذية والمحتوى التالف والصور المتحركة. الحدود: 16–8192 بكسل لكل بعد، وبحد أقصى 25 مليون بكسل.

الحد الافتراضي **5 MiB لكل صورة**. يمكن ضبط `MEDIA_MAX_IMAGE_BYTES` بين 1 KiB و20 MiB. مسار الوسائط الافتراضي مجاور لقاعدة كتالوج المنتجات، وفي تجربة Windows يقع داخل **`data/local-demo/media`**. يمكن تخصيصه بواسطة `MEDIA_STORAGE_PATH`. لا تُحفظ الصور في الذاكرة المؤقتة أو مجلد البناء.

`MediaStorage` واجهة مستقلة بعمليتي `put/get` مع محول قرص محلي دائم. `MEDIA_STORAGE_DRIVER=local` هو المحول المنفذ؛ اختيار محول غير موجود يفشل بوضوح، ولا يدّعي تشغيل تخزين سحابي. يمكن بناء محول object storage لاحقًا خلف الواجهة نفسها. يبقى مجلد الوسائط بحاجة إلى قرص دائم عند استضافة مستقبلية.

واجهات الرفع والاستيراد خاصة بالجلسة وتتحقق من Origin وحجم جسم الطلب تدريجيًا. لا يمكن إسناد ملف محلي يخص تاجرًا آخر إلى المنتج. الصور نفسها تُعرض علنًا على `/media/<random>.webp` لأنها صور متجر؛ لا توجد قائمة عامة بالملفات، ولا تُكشف ملفات metadata. الاستجابة ثابتة النوع مع `nosniff` وCSP مناسب. لا تُحذف البايتات عند إزالة المرجع لحفظ إمكانية عرضها تاريخيًا.

تبقى روابط الصور القديمة قابلة للقراءة والحفظ والنسخ داخل التاجر نفسه. إضافة رابط جديد عبر API لا تتجاوز الاستيراد والفحص، بما فيها الروابط ذات بروتوكول HTTPS المكتوب بأحرف كبيرة. لا تُعطل حماية صور Next.js عالميًا، ولم تُفعّل مصادر عامة غير مقيدة في `next.config.ts`.

## روابط HTTPS

قائمة السماح الافتراضية: `images.unsplash.com` و`images.pexels.com`. يمكن للمشغّل إضافة نطاق CDN عام موثوق إلى `MEDIA_REMOTE_HOSTS` في إعدادات الخادم ثم إعادة التشغيل؛ لا تقبل القائمة wildcards. يمكن رفع ملف من الجهاز دون إعداد نطاق أو حساب خارجي.

كل تحويل يعاد فحصه، مع رفض البروتوكول غير الآمن والاعتمادات داخل الرابط والمنافذ غير القياسية والعناوين الخاصة، وفحص DNS عام، وحد للتحميل ومهلة زمنية. تبقى قائمة النطاقات الموثوقة أساس الأمان؛ هذه ليست خدمة proxy عامة لروابط المستخدمين العشوائية ولا تدّعي تثبيت DNS عند النقل عبر proxy. لا تُحفظ الروابط الموقعة في بيانات الصورة الناتجة. اختبارات التنزيل تستخدم نقلًا محاكى ومحتوى صوريًا فعليًا؛ لا يُدّعى نجاح كل رابط خارجي أو اختبار حساب إعلاني.

## تجربة Windows

1. أوقف النسخة القديمة بـ **Ctrl+C** واحتفظ بمجلدها. نزّل آخر ZIP من [المستودع](https://github.com/zakkoussama1-wq/-) واستخرجه في مجلد جديد.
2. انسخ **`data/local-demo` كاملًا** من النسخة القديمة إلى الجديدة، بما فيه `media` إن وُجد. لا تنقل `node_modules`.
3. مع **Node.js 24** شغّل **START-WINDOWS.cmd** وانتظر **Ready** واترك النافذة مفتوحة.
4. **OPEN-DASHBOARD.cmd ← المنتجات ← إضافة منتج**. اكتب الاسم وSKU والوصف وسعر الخيار. اضغط **اختيار الصور** وحدد ملفات PNG أو JPEG أو WebP.
5. جرّب النجمة لتحديد الرئيسية، والسهمين للترتيب، والاستبدال والإزالة. اختر صورة للخيار، ثم **حفظ المنتج**.
6. أعد تحميل الصفحة وافتح المنتج للتأكد من الصور وSKU والوصف والخيارات. جرّب **نسخ المنتج**؛ يجب أن تحصل النسخة على معرفات جديدة. حذف المنتج يتطلب تأكيدًا ويحفظ بياناته التاريخية.
7. أوقف التطبيق بـ **Ctrl+C**، ثم أعد **START-WINDOWS.cmd** وافتح المنتجات: تبقى الصور والمنتج محفوظين. لا تمسح مجلد البيانات عند التحديث.
8. **OPEN-FORM.cmd** يفتح النموذج الحالي. لعرض منتج آخر فيه فعّل اختيار المنتج من منشئ النموذج أو اربطه بالمنتج بالأدوات القائمة. تبقى الروابط المستقلة والمعرض وتحديث صورة الخيار للمرحلة التالية.

يمكن تشغيل `npm run test:media-restart` لفحص آلي معزول يرفع صورة ويحفظ منتجًا ويوقف الخادم ويعيده ويقارن بايتات الصورة. يحتاج المنفذ 3005 فارغًا، ويستعمل مجلدًا مؤقتًا منفصلًا؛ لا يستخدم بيانات التاجر. نُفذ هذا الفحص على Linux، ولم يُنفذ Windows أصليًا.

أُضيفت ملفات الصور وmetadata إلى نسخ SQLite الاحتياطية مع SHA-256 والتحقق قبل الاسترجاع، وبقيت النسخ القديمة دون صور مقبولة. تعليمات حفظ `data/local-demo` كاملًا هي الأبسط للتجربة. النسخ المنفصلة لـPostgreSQL تخص قاعدة البيانات؛ يُحفظ مجلد الوسائط معها بصورة مستقلة.

## نتيجة التحقق

نجحت 74 حالة متصفح للتجربة المحلية و34 حالة للميزات السابقة، و161 اختبار وحدة؛ تخطيت 4 حالات PostgreSQL لغياب قاعدة اختبار مهيأة في هذه الجولة. نجح البناء وفحص الأنواع وlint والتنسيق. أُعيد فحص الرفع ورفض المحتوى المزيف بعد إضافة فحص التوقيع الثنائي قبل مفكك الصور. نجح فحص إعادة تشغيل الخادم ومطابقة بايتات الصورة.

شُغلت نسخة standalone المبنية محليًا بحسابين تجريبيين وقواعد مؤقتة: رُفض الرفع دون جلسة، وقُبلت الصورة الصحيحة، ومُنع إسنادها إلى منتج التاجر الآخر، وظلت الصور العامة ومرجع 58/69 متاحين. هذا فحص محلي للنسخة المبنية؛ لا يوجد نشر خارجي.

كشف البناء توسع تتبع الملفات بسبب المسارات الديناميكية؛ فُصلت فروع المسارات واستُثنيت بيانات التشغيل من التتبع. ولأن Proxy في هذه النسخة من Next.js كان يحتفظ بمرجع لملف مصادقة تشغيلي، يضيف `npm run build` فحص `postbuild` يستبعد المراجع ويمسح **النسخ المولدة داخل standalone فقط**. اختبار مستقل يثبت بقاء الملفات الأصلية دون تغيير. تحققت كذلك من خلو الناتج وجميع ملفات التتبع من قواعد التشغيل والصور المرفوعة مع بقاء قاعدة المناطق. لم تُرفع نسخ البيانات المولدة أو تُنشر.
