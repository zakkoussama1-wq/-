# إعادة التصميم — المرحلة الأولى

هذه المرحلة تنفذ البداية المحددة في ملف المتطلبات «PREMIUM STRIPE-INSPIRED REDESIGN»: نظام التصميم المشترك، التنقل، والنظرة العامة فقط. إعادة تصميم صفحات الشحن والطلبات والمنتجات والمنشئ ونموذج العميل تنتظر موافقة المستخدم على هذه المرحلة. مستوى التنظيم مستلهم من لوحات SaaS؛ لا تستخدم الواجهة علامة Stripe أو رسومها.

## ما تغير

- ألوان وخطوط ومسافات وحدود وظلال مشتركة في `src/app/workspace.css`، محصورة في مساحة الإدارة حتى يحتفظ نموذج العميل بألوان التاجر.
- أسطح وبطاقات وحالات تحميل وإشعارات قابلة لإعادة الاستخدام. أزرار الإدارة أكثر إحكامًا، مع حالات تركيز مرئية.
- قائمة جانبية فاتحة، مؤشر واضح للقسم النشط، شريط علوي مختصر، وإغلاق قائمة الهاتف بـ Escape مع استعادة التركيز وحصر التنقل بلوحة المفاتيح داخلها.
- نظرة عامة مستقلة تقرأ `/api/orders` المحمي القائم. إجمالي الطلبات وقيمتها والطلبات قيد المراجعة والمسلّمة، مع فلترة الفترة الزمنية.
- مخطط لعدد الطلبات اليومية الفعلية خلال 7 أو 30 يومًا، وتوزيع الحالات. جميع الأيام محسوبة بتوقيت UTC وموسومة بذلك. عند اختيار كل الفترات تكون المقاييس شاملة بينما يعرض المخطط آخر 7 أيام بعنوان واضح.
- جدول يعرض حتى 5 نتائج مع البحث بالاسم والهاتف والرقم والمنتج، وتصفية الحالة، وترتيب التاريخ. زر إدارة الطلبات يفتح الصفحة القائمة لإدارة الطلب وتفاصيله.
- قيمة الطلبات تستبعد الملغاة ولا تُقدّم باعتبارها إيرادات محصّلة. المتجر الفارغ يعرض أصفارًا ورسالة مناسبة، دون طلبات أو نسب نمو مصطنعة. فشل القراءة يعرض إعادة المحاولة بدل بيانات تبدو صحيحة.
- تعريب RTL وترجمة فرنسية وإنجليزية لجميع النصوص الجديدة، مع تنسيق الأرقام والعملات والتواريخ حسب اللغة. أضيف جدول بيانات نصي للمخطط لقارئ الشاشة، ويمكن تمرير جدول الطلبات بلوحة المفاتيح على الشاشات الصغيرة.

## الحفظ ونقطة الرجوع

قبل التغيير أُنشئ وسم Git: `checkpoint/pre-stripe-redesign-20261101` عند `80c37b8`.

لا تتطلب المرحلة ترحيل قاعدة بيانات. لم تتغير مخططات SQLite/PostgreSQL أو ملفات بيانات الولايات والبلديات أو أسعار الشحن أو مسارات API. اختبارات المتصفح تستخدم قواعد مؤقتة مستقلة؛ بيانات الجدول المحددة في اختبار الواجهة اعتراض لاستجابة API للاختبار فقط، ولا تُحفظ في بيانات أي متجر.

## المعاينة على Windows

1. أوقف النسخة القديمة بـ Ctrl+C واترك مجلدها محفوظًا.
2. نزّل آخر نسخة من [GitHub](https://github.com/zakkoussama1-wq/-) عبر **Code → Download ZIP** واستخرجها في مجلد جديد.
3. للحفاظ على طلباتك وأسعارك وتصميمك: انسخ `data\local-demo` من المجلد القديم إلى `data` في المجلد الجديد. لا تنقل `node_modules` ولا تحذف المجلد القديم.
4. مع Node.js 24 LTS، شغّل **START-WINDOWS.cmd** وانتظر **Ready** واترك النافذة مفتوحة.
5. اضغط **OPEN-DASHBOARD.cmd** لعرض النظرة العامة الجديدة، أو افتح `http://localhost:3000/dashboard` في Firefox على حاسوبك.
6. اضغط **OPEN-FORM.cmd** للنموذج القائم، أو افتح `http://localhost:3000/form`. احفظ طلبًا وهميًا ثم ارجع إلى النظرة العامة واضغط **تحديث**.
7. جرّب اللغة من الشريط العلوي، والفترة الزمنية والبحث وترتيب التاريخ، وفتح قسم الطلبات.

لا توجد في هذه الجلسة أداة Preview خارجي. روابط localhost تعمل على الجهاز الذي يشغّل التطبيق. لم يُنشر التطبيق ولم يُربط Shopify.

الأوامر البديلة داخل مجلد المشروع:

```bat
npm.cmd ci
npm.cmd run dev:local
```

تفاصيل التشغيل وحفظ البيانات وحلول المشاكل في [دليل Windows](../WINDOWS-START-HERE.md).

## التحقق

- `npm run typecheck` و`npm run lint` و`npm run format:check`.
- `npm test`: يشمل اختبارات حساب القيم واستبعاد الملغى وحدود الأيام بتوقيت UTC وعدم اختلاق أرقام للمتجر الفارغ.
- `npm run test:local`: اختبارات النظرة العامة باللغات الثلاث على الهاتف والحاسوب، وفشل API وإعادة المحاولة، إضافة إلى اختبارات المنشئ والطلبات وأسعار التوصيل القائمة.
- `npm run test:e2e` لاختبارات الميزات السابقة، ثم `npm run build`.

التحقق يجري في بيئة Linux؛ لا يُدّعى تنفيذ اختبار Windows أصلي. لا تحتاج التجربة استضافة أو ربطًا خارجيًا.

نتائج التحقق لهذه المرحلة: 145 اختبار وحدة/تكامل ناجح، و4 اختبارات PostgreSQL متخطاة دون قاعدة اختبار مهيأة؛ 34 اختبار متصفح للميزات القائمة و18 للتجربة المحلية ناجحة. فُحصت أيضًا 12 حالة عرض (360 و768 و1024 و1440 بكسل × اللغات الثلاث) دون تجاوز عرض الصفحة، وحُفظت أربع لقطات من التطبيق بثلاثة طلبات وهمية في قاعدة مؤقتة، دون أخطاء متصفح.
