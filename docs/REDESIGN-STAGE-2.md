# إعادة التصميم — صفحة الشحن

هذه المرحلة تقتصر على إدارة أسعار الشحن. تبقى إعادة تصميم الطلبات والمنتجات والمنشئ ونموذج العميل للمراحل التالية بعد الموافقة. احتُفظ بجميع الملفات والميزات؛ لا يوجد نشر أو ربط Shopify.

## ما تغير

- جدول للولايات بدل البطاقات الطويلة، بأعمدة الرمز والاسم وسعر المنزل والمكتب وحالة كل طريقة والتعديل المتقدم. مصدر السعر ظاهر: قاعدة ولاية خاصة أو السعر الافتراضي.
- تحرير الأسعار والحالات داخل الجدول. التعديلات المعلّقة مميزة، وتُحفظ معًا من زر **حفظ التعديلات**، أو تُلغى دون مساس بالأسعار المحفوظة. تبقى التعديلات موجودة عند الانتقال بين صفحات الجدول.
- البحث بالرمز أو الاسم العربي أو اللاتيني، والتصفية حسب القاعدة وحالة التوصيل، وترتيب الرمز والاسم، وتقسيم إلى صفحات مع خيار عرض الكل.
- تحديد ولايات عبر عدة صفحات، وتحديد جميع نتائج البحث، وتعديل جماعي كامل، وتوصيل منزل مجاني للمحدد، وإعادة القاعدة إلى السعر الأقل أولوية بعد التأكيد.
- نوافذ للسعر الافتراضي وقاعدة الولاية واستثناء البلدية وCSV، مع احتواء التركيز ودعم Escape واستعادة التركيز. يبقى اختبار السعر الفعلي من الخادم متاحًا من القسم القابل للفتح أسفل الصفحة.
- إعداد المكتب العام ظاهر قبل الجدول، وهو مستقل عن تفعيل المكتب وسعره في كل قاعدة. تعطيل المنطقة يمنع التوصيل حتى لو كانت طريقة داخلها مفعّلة.
- استيراد CSV لا يحفظ بمجرد اختيار الملف: راجع الملف ثم اضغط **استيراد وحفظ**. تُرفض العملية كاملة عند خطأ أو صف مكرر؛ التصدير يحتفظ بتنسيق CSV الحالي المتوافق مع Excel، بما فيه رؤوس الأعمدة العربية للتوافق مع الملفات السابقة. لا تغيّر رؤوس القالب.
- تُستخدم مكونات وألوان المرحلة الأولى، مع حالات تحميل وخطأ وإشعار نجاح وترجمة عربية وفرنسية وإنجليزية، وجدول يمكن تمريره أفقيًا على الهاتف ولوحة المفاتيح.

## الحفاظ على قواعد التسعير والبيانات

لم يتغير API أو مخطط قواعد البيانات أو بيانات 58/69 ولاية و1,541 بلدية. أولوية التسعير تبقى: **البلدية ← الولاية ← الافتراضي**. تعديل صف ولاية يحافظ على خصائص القاعدة الأخرى مثل مدة التوصيل وسعر الطريقة المعطلة. لا يعدّل استثناءات البلديات ولا أسعار النظام الإداري الآخر.

يعتمد الحفظ على رقم المراجعة القائم. عند وجود تعديل أحدث في جلسة أخرى تُرفض الكتابة، وتبقى تعديلات الجدول ظاهرة حتى تصححها أو تعيد تحميل البيانات بعد تأكيد تجاهلها. الحفظ الناجح يخطر تبويبات النموذج المفتوحة لإعادة التسعير.

نقطة الرجوع قبل هذه المرحلة: `checkpoint/pre-shipping-redesign-20261101` عند `856adf8`.

## التجربة على Windows

1. أوقف النسخة القديمة بـ **Ctrl+C**. نزّل آخر نسخة من [GitHub](https://github.com/zakkoussama1-wq/-) عبر **Code → Download ZIP** واستخرجها في مجلد جديد.
2. انسخ `data\local-demo` من النسخة القديمة إلى مجلد `data` الجديد للاحتفاظ بالطلبات والأسعار والتصميم. احتفظ بالمجلد القديم؛ لا تنقل `node_modules`.
3. شغّل **START-WINDOWS.cmd** مع Node.js 24 وانتظر **Ready**، واترك النافذة مفتوحة.
4. اضغط **OPEN-DASHBOARD.cmd** ثم **أسعار الشحن**. عدّل سعر المنزل أو المكتب في صف ولاية واضغط **حفظ التعديلات**.
5. افتح **OPEN-FORM.cmd** في تبويب آخر، واختر الولاية والبلدية وطريقة التوصيل. يظهر السعر الجديد بعد الحفظ. إذا كانت البلدية تملك استثناءً محفوظًا، يبقى سعرها هو صاحب الأولوية.
6. لتغيير السعر الافتراضي اضغط **إعداد السعر الافتراضي**. لتطبيق قاعدة خاصة على جميع الولايات، استخدم **تحديد كل نتائج البحث** دون بحث أو تصفية، ثم **تعديل جماعي** واحفظ. استثناءات البلديات تبقى محفوظة في الحالتين.
7. جرّب **إضافة تجاوز بلدية**، وتصدير CSV ثم استيراده، واللغات الثلاث من الشريط العلوي.

على حاسوبك بعد التشغيل: `http://localhost:3000/dashboard` للإدارة، و`http://localhost:3000/form` للنموذج. لا تتوفر أداة Preview خارجي في هذه الجلسة. [دليل Windows الكامل](../WINDOWS-START-HERE.md).

## التحقق

اختبارات المرحلة تستخدم قواعد مؤقتة مستقلة، ولا تستبدل بيانات المتجر. تشمل حفظ الأسعار والحالات وأولوية البلدية، وبقاء سعر المكتب عند تعطيله ومدة التوصيل، وعدم تغيير الأسعار قبل الحفظ، والتحديث بين تبويبات الإدارة والنموذج، والتحديد عبر الصفحات والترتيب والبحث، وتعارض المراجعة، ورفض CSV غير الصالح دون كتابة جزئية.

أوامر الفحص: `npm run typecheck` و`npm run lint` و`npm run format:check` و`npm test` و`npm run build` و`npm run test:local` و`npm run test:e2e`. تُشغّل خوادم الاختبار والبناء بالتتابع. التحقق يجري على Linux؛ لا يُدّعى إجراء اختبار Windows أصلي.

نتيجة التحقق: نجحت فحوص الأنواع وLint والتنسيق وبناء الإنتاج. نجح 145 اختبار وحدة/تكامل، وتُخطيت 4 اختبارات PostgreSQL لعدم تهيئة قاعدة اختبار لها في هذه الجولة. نجح 34 اختبار متصفح للميزات القائمة و30 للتجربة المحلية، منها 12 لجدول الشحن وأخطائه باللغات الثلاث على الهاتف والحاسوب. نجحت 12 حالة عرض بين 360 و1440 بكسل دون تجاوز عرض الصفحة، وحُفظت خمس لقطات من التطبيق دون أخطاء متصفح. لم تتغير ملفات البيانات أو مخططات التخزين.
