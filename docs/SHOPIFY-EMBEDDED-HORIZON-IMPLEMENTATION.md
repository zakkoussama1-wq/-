# نتيجة التنفيذ المحلي: Shopify Admin وHorizon

## ما تحقق وما لم يتحقق

وافق المالك على رفع هذه النسخة المجهّزة إلى main بعد المراجعة. لم تتغير
إعدادات Render أو Shopify أو قاعدة البيانات الحقيقية، ولم يُنشأ طلب Shopify أو
يُرسل Purchase أو إشعار. DZ_SHOPIFY_ORDER_SYNC=0 وحواجز single_order/outbox باقية.

المراجعة قبل التعديل في [تقرير البنية](SHOPIFY-EMBEDDED-HORIZON-REVIEW.md).
مصدر Horizon المرجعي هو مستودع Shopify الرسمي عند
99604908f1af345214ece67b9e2c5660886f37ea. اختبارات iframe تستخدم **بنية DOM مختصرة**
مستمدة من هذا المصدر؛ ليست Theme Editor حقيقيًا ولا تنفيذًا كاملًا لمحرك Shopify Liquid.
اختبارات لوحة Next.js تستخدم App Bridge وهميًا؛ لا تثبت ظهور القائمة الأصلية في
Shopify Admin قبل ضبط التطبيق ومراجعته في الحساب الحقيقي.

جرت محاولة قراءة h8vsym-t0.myshopify.com للقراءة فقط. رفض وكيل شبكة البيئة الاتصال
بـ403 CONNECT قبل الوصول إلى Shopify، كما حُجب WEBI وshopify.dev. لذلك **السبب الحي
المحدد لاختفاء البلوك في المتجر غير محسوم**. لا توجد أدلة على أن Cookies سببه.
لم نفترض أن إصلاحًا محليًا يثبت تشغيل المتجر الحقيقي.

## المسار الأول: لوحة Shopify

أُضيفت نقطة دخول /shopify مع خمسة مسارات: builder وdesign وshipping وintegrations
وsettings. تُستخدم شيفرة App Bridge الرسمية عبر
https://cdn.shopify.com/shopifycloud/app-bridge.js وmeta shopify-api-key، وعنصر
ui-nav-menu وروابط داخلية مع rel=home. روجعت واجهتا idToken وui-nav-menu في حزمة
Shopify الرسمية @shopify/app-bridge-types 0.7.4. لا تُنسخ واجهة WEBI أو علامته.

المصادقة الجديدة محصورة في /api/embedded/*:

- يطلب العميل idToken جديدًا لكل اتصال، ولا يخزنه في Cookies أو localStorage.
- تتحقق مكتبة Shopify الرسمية من HS256 وaudience والتوقيت، مع فحص dest وiss وsub
  وsid والعمر القصير، ثم يُقرأ تثبيت المتجر الفعال وربطه بالحساب من PostgreSQL.
- لا تختار shop أو store أو merchantId في استعلام المتصفح التاجر؛ تُرفض هذه المحددات.
- لا تحل جلسة قديمة من Cookie محل JWT، ولا يمنح JWT وحده وصولًا إلى /api/orders القديمة.
- الكتابة تتطلب Origin الذي يطابق أصل التطبيق المضبوط في SHOPIFY_REDIRECT_URI
  وSec-Fetch-Site=same-origin عند وجوده. لا تسمح واجهاتنا بـCORS مفتوح.
- يُقيد CSP frame-ancestors إلى Shopify Admin ونطاق myshopify صالح؛ لا يُستخدم نطاق
  الاستعلام لإعطاء صلاحية بيانات. لا تُطبع أخطاء SDK التي قد تتضمن التوكن.

لا يوجد مدير منتجات أو طلبات جديد. يعيد اختيار منتج المعاينة قراءة كتالوج Shopify
المتزامن الخاص بالمتجر من shopify_catalog في معاملة READ ONLY؛ لا يقرأ منتجات
local/demo ولا يجدّد OAuth أو يطلق مزامنة. السعر والتحقق النهائي يأتيان من قراءة
Shopify الحالية عبر نفس نموذج المتجر ومحرك التسعير القائمين.

أُعيد استخدام صفحة الشحن الحالية ومحركها مع ناقل مصادقة يختلف فقط تحت /shopify.
خارجها يبقى ناقل اللوحة القديمة كما هو. رابط CSV داخل Embedded يستخدم طلبًا مصادقًا
ثم ملفًا محليًا، دون وضع Session Token في URL. صفحة التكاملات تفحص الصلاحيات الحالية
للقراءة فقط؛ **تحرير إعدادات التتبع الإنتاجي لم يُنقل إلى هذه الصفحة** ولم يُفعّل.

## المسار الثاني: التخصيص وظهور Horizon

عيوب الكود المثبتة ومعالجتها:

1. كان البلوك يخرج فراغًا إذا غاب product، بلا fallback إلى closest.product.
   أصبح يستخدم closest.product ثم product، ويعرض PRODUCT_CONTEXT_MISSING عند غياب الاثنين.
2. لم تكن هناك واجهة انتظار مرئية قبل تشغيل JavaScript. أُضيفت stylesheet صغيرة
   وحالة LOADER_PENDING بنص مفهوم حتى عند عدم تشغيل ملف التهيئة.
3. كان التحميل معتمدًا على IntersectionObserver وحده. في Theme Editor أصبح مباشرًا،
   مع fallback عند غياب Observer، ووقت أقصى لتنزيل runtime ورسالة وإعادة محاولة.
4. لم تكن أحداث Horizon مغطاة. أُضيف variant:update وproduct:select مع promise كما
   في المصدر الحالي، وتفضيل form داخل product-form-component على النماذج الثانوية.
   يُعطل التحقق أثناء اختيار Variant غير محسوم، وتُهمل النتائج القديمة/العناصر المنفصلة.
5. كانت إعدادات الحقول/الترتيب تُستبدل جزئيًا، والألوان الافتراضية للبلوك تغلب تصميم
   المنشئ. أصبح تصميم التاجر المصدر الافتراضي، مع خيار صريح لاستثناء ألوان/نصوص البلوك.
6. Bootstrap يعيد إعدادات العرض الكاملة: الحقول وإلزاميتها وترتيبها والنصوص والألوان
   والخط والحجم واللغة والتوصيل. إضافات JSON ذات defaults ولا تحتاج ترحيل جداول.
   يتحقق الخادم من hidden/optional/required والمنطقة الثابتة والكمية وإتاحة التوصيل.
7. معاينة اللوحة تستخدم مكون النموذج وCSS نفسيهما داخل Shadow DOM، وليست رسمة بديلة.
   تظهر تغييرات العرض فورًا، بينما يلزم حفظ تغيير السياسة قبل اختبار الحساب النهائي.

الواجهة عربية/فرنسية/إنجليزية. النصوص الافتراضية تُترجم؛ النص المخصص الذي يدخله
التاجر يبقى كما كتبه. الخطوط اختيارات آمنة محلية: system/serif/theme، دون تحميل خطوط
خارجية عشوائية. تُدعم أسماء متغيرات الخط في Horizon والثيمات الشائعة. لا تُغير واجهة
المتجر اتجاه أو لغة الثيم. لا يُختلق مكتب أو عنوان أو سعر.

أُبقي officePickupInstructions نصًا حتى عند عدم ضبطه للحفاظ على توافق استجابة
الخادم مع runtime المرحلة الثانية السابق. ترتيب نشر مستقبلي: الخادم أولًا، ثم
إصدار الامتداد بعد المراجعة؛ نشر runtime الجديد قبل الخادم القديم لا يضمن التوافق.

## التشخيص المرئي الآمن

| الرمز                                        | الدلالة                                                    |
| -------------------------------------------- | ---------------------------------------------------------- |
| PRODUCT_CONTEXT_MISSING                      | لا يوجد سياق منتج في Liquid                                |
| LOADER_PENDING                               | ظهر Liquid؛ ملف التهيئة لم يُكمل التشغيل بعد               |
| RUNTIME_URL_MISSING / RUNTIME_URL_INVALID    | أصل runtime غير موجود أو غير موثوق                         |
| RUNTIME_DOWNLOAD_FAILED / RUNTIME_TIMEOUT    | تعذر تنزيل runtime أو انتهت مهلته                          |
| RUNTIME_NOT_REGISTERED                       | نزل الملف لكنه لم يسجل مكون النموذج                        |
| FORM_RESPONSE_INVALID                        | استجابة Bootstrap لا تطابق مخطط النموذج                    |
| PROXY_INVALID / ORIGIN_DENIED                | فشل توقيع Proxy أو تطابق النطاق                            |
| CATALOG_AUTH_UNAVAILABLE                     | Offline Token الحالي غير قابل للاستخدام؛ لا يُجدد تلقائيًا |
| CATALOG_UNAVAILABLE / STOREFRONT_UNAVAILABLE | فشل قراءة الكتالوج أو الخدمة؛ لا تُكشف تفاصيل الاتصال      |
| STOREFRONT_POLICY_UNSUPPORTED                | تقسيم جغرافي غير مدعوم في واجهة المتجر الحالية             |
| STORE_CURRENCY_UNSUPPORTED                   | العملة/هوية المتجر لا تطابق شروط القراءة الآمنة            |

لا تُعرض الاستثناءات الخام أو التوكنات أو مفاتيح التشفير أو بيانات العملاء في الرسائل.
الواجهة تتحقق فقط وتعيد persisted=false وshopifyOrderCreated=false دائمًا في النجاح.

## حدود الجاهزية وخطوات لاحقة للمالك — لم تُنفذ

- DZ_SHOPIFY_EMBEDDED=0 افتراضيًا في .env.example. بعد مراجعة الكود واختباره في حساب
  التطبيق الصحيح فقط يمكن للمالك ضبطه إلى 1، ثم ضبط embedded=true وapplication_url
  إلى https://APP_HOST/shopify في إعداد تطبيق Shopify. لا نعدل تلك الإعدادات تلقائيًا.
- إصلاح عرض Horizon مستقل عن تفعيل Embedded؛ مسار /apps/dz-cod إلى /api/storefront
  لم يتغير. الحفاظ على DZ_SHOPIFY_ORDER_SYNC=0 لا يمنع عرض/حساب النموذج.
- لا تطلب واجهة الإدارة/التنقل صلاحية write_orders. يظل read_products مطلوبًا لقراءة
  المنتج، وتبقى متطلبات App Proxy السابقة كما هي. لم تُضف scopes إلى OAuth.
- هذه نقطة دخول للمتاجر المرتبطة والمثبتة مسبقًا. **التركيب التلقائي لأول متجر جديد
  وربط حسابه/Token Exchange ليس منفذًا هنا**؛ المتجر غير المرتبط يُرفض بأمان.
  يظل تدفق OAuth القديم والإدارة القديمة متاحين. تفعيل نمط التثبيت العام يحتاج مراجعة
  منفصلة لهوية الحساب والتوزيع وصلاحيات الموظفين، وليس إنشاء حسابات وهمية تلقائيًا.
- لا يوجد ضبط تفصيلي جديد لأدوار الموظفين؛ يتحقق JWT من وصول جلسة Shopify للتطبيق
  والتاجر المرتبط. يجب مراجعة متطلبات الموظفين قبل تعميم التطبيق على متاجر متعددة.
- تبقى جغرافيا المتجر legacy58 والعملة DZD والكمية 1–10. لا يغيّر هذا العمل أسعار
  الشحن الحقيقية أو يضيف كتالوج مكاتب أو ضرائب/عملة أو معالجة طلبات إنتاجية.
- ينبغي فحص native App Navigation وApp Bridge وTheme Editor وملفات CDN وProxy في
  المتجر الحقيقي بعد نشر معتمد. بناء Render لا يصدر Theme Extension تلقائيًا.

لفحص **النسخة المنشورة الحالية دون نشر تعديل** بخطوة من المتصفح: في صفحة المنتج
افتح مصدر الصفحة بـCtrl+U، وابحث عن dz-cod-form، ثم أرسل مقطع البلوك المحيط به فقط.
لا حاجة إلى Console أو Cookies أو أي توكن. غياب البلوك أو وجود خصائصه وأصل runtime
سيفصل بين فشل Liquid ومراحل JavaScript/Proxy؛ لا ترسل مصدر الصفحة كله.

## إعادة الاختبارات محليًا

```sh
POSTGRES_TEST_URL=LOCAL_DISPOSABLE_POSTGRES_URL npm test -- --maxWorkers=2
npm run lint
npm run typecheck
npm run format:check
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:storefront
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:embedded
npm run storefront:build
npx --yes @shopify/cli@5.0.1 theme check --path extensions/dz-cod-form --no-input
```

test:embedded يشغل Next محليًا بإعدادات صناعية وتعطيل التكاملات الحقيقية وDATABASE_URL
فارغًا، ويعترض App Bridge وطلبات API في المتصفح. اختبارات JWT/SQL منفصلة تستعمل
PostgreSQL 18 معزولًا وتواقيع صناعية يتحقق منها SDK الرسمي. لا تحتاج إعدادات الإنتاج.
نتائج التشغيل النهائية وبناء Docker تُذكر في تقرير التسليم بعد اكتمال الفحوصات.
