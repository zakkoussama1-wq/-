# مصادر بيانات الجغرافيا ومراجعتها

هذه بيانات مرجعية فعلية، وليست قوائم عرض مختلقة. النظام الافتراضي ٥٨ ولاية. يحتوي كل نظام على البلديات نفسها وعددها ١٥٤١؛ تتغير علاقة الولاية فقط. الأسماء العربية واللاتينية محفوظة كما في المصدر الأساسي، بما فيها اختلافات التهجئة المحلية.

كلاهما MIT، وتوجد نسخة الترخيص الأصلية مع كل مصدر داخل `sources`. تسجل `provenance.json` بصمات SHA-256 للملفات الأصلية. الاستيراد يرفض تغير البصمات؛ لا تعدل ملفات المصدر أو البصمات لإخفاء فشل التحقق. تحديث المصادر عمل مراجعة مقصود يتطلب إعادة التدقيق وتوثيق النتائج.

## ما فُحص وما بقي

- مخطط السجلات، الأعداد، تفرد معرّفات المصدر، عدم وجود بلديات يتيمة، اتساق أسماء الولايات داخل الملف.
- وجود ٥٨ ولاية في النظام القديم و٦٩ في المحدّث، و١٥٤١ بلدية في كل منهما.
- المقارنة أظهرت أن ملف ٦٩ في المصدر الأول ينقل ٩٢ بلدية ويخالف قوائم القانون المنقولة في المصدر الثاني في ٣٨ علاقة. لا يُستخدم هذا الملف مباشرة في التطبيق.
- `transfers-2026.json` يسجل نقل ١٠٨ بلديات وفق القوائم المنقولة: ١٢، ٨، ٥، ٤، ٤، ٦، ١٠، ٨، ٢١، ٢٣، ٧ بلديات للولايات ٥٩–٦٩ على الترتيب. بقية البلديات تحتفظ بالآباء من قاعدة ٥٨.
- يجري التطابق بأسماء عربية أو لاتينية مطبّعة داخل الولاية الأصلية، مع ثماني مطابقات أسماء راجعتها الشيفرة عبر معرّفات ثابتة موثقة في ملف النقل. لا يوجد تقريب عشوائي أو توليد أسماء. تتضمن الاختلافات `Abdelkader Azil`/`Azil Abedelkader` و`Ouled Maaref`/`Ouled Emaaraf`.
- بوسعادة (`dz:commune:1006`) وعين الملح (`dz:commune:996`) تتبعان المسيلة ٢٨ في نظام ٥٨ وبوسعادة ٦٨ في النظام المحدّث. تبلبالة تبقى ضمن بني عباس ٥٢ في النظامين؛ المرجع الثاني يضعها في بشار، ولم ننقل هذا الاختلاف إلى قاعدة ٥٨.
- `audit.json` يحتوي كل الاختلافات الـ٣٨ على مستوى البلدية، وليس مجرد عدد إجمالي.

**حد المراجعة الحالي:** لم يتم تنزيل ومطابقة ملف الجريدة الرسمية نفسه. رُفض الاتصال عبر وكيل الشبكة بـHTTP 403. المرجع المقصود هو [الجريدة الرسمية الفرنسية رقم ٢٥ لسنة ٢٠٢٦](https://www.joradp.dz/FTP/JO-FRANCAIS/2026/F2026025.pdf)، القانون ٢٦-٠٦. المصدر الثاني ينقل النص لكنه ليس موقع الجريدة الرسمي. لذلك نُظهر حالة «مرجع ثانوي قيد المطابقة الرسمية» في واجهة نظام ٦٩ وفي استجابة API. نجاح اختبارات الأعداد والخرائط لا يثبت وحده صحة النص القانوني المنقول. يلزم التحقق المباشر قبل اعتماد هذه الخريطة لتلبية طلبات حقيقية. لا توجد طلبات فعلية أصلًا في هذا الإصدار.

تم حفظ إضافة `www.joradp.dz` و`joradp.dz` في مسودة شبكة البيئة مع الحفاظ على presets الموجودة. حفظ المسودة لا يطبّقها على الشبكة الجارية؛ بعد تطبيق الوصول يجب تنزيل المرجع ومراجعة العضوية والأسماء وتوثيق دليل المطابقة، ثم تحديث حالة التحقق واختبارها. لا يكفي تغيير العلم إلى «متحقق».

## المعرّفات والبحث

`dz:wilaya:28` يستخدم رمز الولاية. `dz:commune:1006` مبني على معرّف المصدر الأول الداخلي؛ **ليس رمزًا رسميًا وطنيًا للبلدية**. يظل ثابتًا عند تبديل النظام ولا يُشتق من الاسم أو رقم الولاية. تبقى قيم المصدر الأصلية في `sourceId`.

البحث يزيل الحركات والتطويل وفروق أشكال الألف والألف المقصورة، ويطبع لكنات اللاتينية والأحرف الكبيرة وعلامات الفصل. لا يغير الأسماء المخزنة للعرض. تعيد واجهة البلديات نتائج الولاية المختارة فقط، ولا تبحث في بلديات الولايات الأخرى.

## الاستيراد والتخزين

```sh
npm run geo:import
npm run geo:check
npm run db:seed
```

الاستيراد يعمل دون شبكة باستخدام النسخ المرخّصة المثبتة، ويولد `catalog.json` و`audit.json` بصورة حتمية. `geo:check` يتحقق من مطابقة المخرجات ولا يغيرها. بذر SQLite يكتب قاعدة جديدة في ملف مؤقت، داخل معاملة وبقيود مراجع ومفاتيح فريدة، ثم يستبدل قاعدة الجغرافيا ذرّيًا. لا يحتوي الملف على بيانات عملاء أو شحن أو طلبات؛ إعادة البذر تعيد بناء البيانات المرجعية فقط. المسار الافتراضي `data/geography.sqlite` متجاهل في Git وقابل لإعادة الإنشاء. يمكن تعيين مسار مطلق بديل عبر `GEOGRAPHY_DATABASE_PATH`، مع استخدام القيمة نفسها في البذر والتشغيل.
